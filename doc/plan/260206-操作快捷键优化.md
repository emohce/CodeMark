| **搜索** | 部分实现 | 有搜索框与 `startSearch()`；无「普通字符即时搜索、匹配高亮、方向键在匹配间移动、Enter 选中等」完整交互。 |

### 阶段 2：Editor 右键与快捷键（自适应新增/编辑、删除）

| 2.2 | Editor 右键：单一条目「新增/编辑」 | 新建 Action 或合并现有 | 根据当前行有无 CodeMark 显示 "Add CodeMark Here" 或 "Edit CodeMark"；同一 action，`update()` 中设 text。 |
| 2.3 | Editor 右键：删除（仅当行有 CodeMark 时显示） | 新建 Action | `update()` 中仅在有 CodeMark 时 enable 并显示；执行时调已有删除逻辑 + 确认。 |
| 2.4 | Shift+F2：补齐实现与一致性 | `CreateBookmarkAtCaretAction`、`plugin.xml` | 现状：已实现「有则编辑/更新、无则新增」。待补齐：1) 判断逻辑改用 `BookmarkIndexService`；2) 右键菜单文案与 Action 文案一致（Add vs Edit）。 |

### 阶段 4：搜索交互增强

**目标**：普通字符即时搜索、匹配高亮、方向键在匹配间移动、Enter 选中并更新缓存、取消搜索保持高亮节点。

| 序号 | 任务 | 涉及文件/位置 | 说明 |
|------|------|----------------|------|
| 4.1 | 搜索触发方式 | `BookmarkPanel` 搜索框 | 改为输入即搜（或 debounce 300ms），不再仅「点击 Search」；保留搜索文案展示。 |
| 4.2 | 记住展开状态 | `BookmarkPanel` / ViewModel | 搜索开始前保存当前 `tree.getExpandedPaths()`；搜索过程中在「初始展开状态」上做过滤/高亮，不改变用户原有展开结构（或按需求「动态更新展示」规则实现）。 |
| 4.3 | 匹配高亮 | 树 Renderer 或 CellRenderer | **仅匹配字符高亮**：在节点文本中对匹配到的关键字做高亮（如 `<b>keyword</b>` 或匹配片段加粗/变色），不做整行或整节点背景高亮；不过滤掉不匹配节点（即「不用过滤不展示」）。 |
| 4.4 | 方向键在匹配项间移动 | 树 KeyListener / InputMap | 搜索激活时：↑/↓ 在「匹配节点列表」中移动高亮。**约定**：搜索框内左右键屏蔽（不移动光标）；树获得焦点时左右键仍为树节点的折叠/展开（与现有树 Left/Right 一致）。 |
| 4.5 | Enter 选中并更新缓存 | 同上 | 高亮在某一 match 上时 Enter：选中该节点、导航（若为 mark）、`setLastSelectedNodeId`。 |
| 4.6 | 取消搜索 | 清除搜索框 / Escape | 恢复初始展开状态；高亮保留在「最后高亮节点」并设为当前节点缓存。 |
| 4.7 | 符合条件自动展开 | 可选 | 若需求「节点符合条件则自动展开」，在 4.2 的展示逻辑里对匹配到的父节点做 expand。 |

**验收**：输入即搜、匹配高亮、↑↓ 移动、Enter 选中并更新缓存、取消后状态与缓存正确。
